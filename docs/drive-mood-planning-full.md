# Drive Mood 기획서 (전체 버전)

> 현대자동차그룹 차량용 앱 개발 공모전
> 작성일: 2026-10-27
> 문서 상태: 기준 문서

Drive Mood의 기능, 사용 시나리오, 개발 범위는 이 문서를 기준으로 관리한다. 기획 초안과 시연 자료는 이 문서를 참조하며, 문서 간 내용이 다르면 이 문서를 우선한다.

## 1. 앱 한 줄 소개
운전 패턴을 리듬으로 읽고, 데이터에서 나온 짧은 문장으로 공감하며, 필요할 때 호흡으로 리듬을 맞춰주는 인카 동반자

## 2. 기획 배경
장시간 운전 시 피로와 긴장으로 운전 리듬이 흐트러지지만, 운전자는 이를 스스로 인지하기 어렵다. 기존 인카 앱은 일반적인 알림이나 콘텐츠 재생에 그쳐, 운전자의 실제 운전 패턴을 해석하고 공감하는 경험이 부족하다. 차량이 이미 보유한 조향각·브레이크·운전 시간·경로 데이터만으로도 개인화된 케어가 가능하다.

## 3. 핵심 기능

### 3.1 운전 리듬 시각화
조향각(`getCurrentSteeringWheelAngle`)과 브레이크 패턴을 리듬으로 해석하여 화면 하단에 파동으로 표현한다.
- 안정 운전: 작은 폭의 조향 보정이 일정한 주기로 나타남 → 부드러운 파란 파동
- 변화가 커진 리듬: 조향 보정의 변화량과 방향 전환이 이어짐 → 주황 파동
- 파동은 관찰된 차량 신호를 표현한다. 피로·긴장·안전도를 진단하지 않는다. 주행 중에는 간단한 상태·문장과 상태 일러스트를 표시한다. 0.4.3의 일러스트에는 상태 변화 전에도 작은 반복 움직임을 시범 적용했다(10절). 관찰 파형과 호흡 안내는 주차 화면에서 제공한다.

### 3.2 마이크로 스토리
데이터 조건(운전 시간, 리듬 상태, 시간대, 경로, 좌석 점유)을 조합해 생성되는 짧은 공감 문장.
예시: “오늘따라 손이 편한 하루네요.”, “어두운 길에서 손이 조금 긴장했어요.”

### 3.3 숨 고르기 가이드
리듬 변화가 이어지면 안전하게 주차한 뒤 쉬어가도록 짧게 제안한다. 실제 차량의 주차(P) 상태와 AAOS 주행 제한 해제가 확인된 경우에 30초 호흡 가이드를 시작한다. 3초 들숨·3초 날숨을 5회 안내하며, 실제 차량 파형과 호흡 안내 파형을 구분해 겹쳐 보여준다. 동시에 현재 공조·앰비언트 상태와 제안 상태를 나란히 표시한다. 주차 해제나 앱 화면 이탈 시 호흡 안내를 중단한다.

### 3.4 도착 리포트
도착 시 “중간중간 리듬이 흔들렸지만, 잘 도착하셨어요”라는 마이크로 스토리와 오늘의 리듬 요약을 제공한다.

## 4. 사용 시나리오
장거리 운전 중 리듬 변화 관찰 → 주차 후 숨 고르기 → 다음 주행의 실제 리듬 확인 → 도착·주차 후 리포트

장거리 운전 중(예: 서울→부산), 92분 경과 후 조향 변화가 이어지면 “손의 움직임이 조금 바빠졌어요. 긴 시간을 달려왔네요. 안전하게 주차한 뒤 잠깐 쉬어가도 좋아요.”라고 안내한다. 운전 중 화면은 문장·현재 리듬과 상태 일러스트를 표시한다. 주차 후 운전자가 수락하면 30초 호흡 원형 안내와 차량·호흡 파형 비교, 현재 실내와 제안 상태를 보여준다. 완료 시 “잠깐 숨을 고르셨어요. 다음 주행에서 리듬을 다시 살펴볼게요.”라고 안내한다. 이후 실제 신호가 일정하게 관찰될 때 파형과 상태를 갱신하며, 호흡을 했다는 이유로 안정화 결과를 만들지 않는다. 내비게이션 도착 이벤트와 주차 상태가 확인되거나 사용자가 주차 후 기록을 마치면 리포트를 저장한다.

## 5. 사용 API

구현 범위는 Vehicle State(`CAR_DRIVE`, `CAR_CLIMATE`, `CAR_LIGHTS`, `CAR_SEATS`)와 NaviHelper API를 활용한다.

- `getCurrentSteeringWheelAngle`
- `getCurrentBrakePedalStatus`
- `getTripCurrentDrivingTime`
- `getRouteStateInfo`
- `getHvacTemperatureCurrent`, `getAmbientLightBrightness` 등

## 6. 차별점 및 기대효과
운전 리듬을 읽고 맞춰주는 경험을 제공한다.

**차량 특화 요소**: 조향각, 브레이크, 운전 시간, 경로, 공조·라이트 상태를 복합 활용. 외부 앱으로는 불가능한 실시간 차량 데이터 기반 경험.

장거리·통근 운전자에게 운전 패턴을 리듬으로 해석하고 짧게 케어하는 새로운 경험을 제공한다. 전 차종에 적용 가능하며, 외부 앱으로 구현하기 어려운 차량 데이터 복합 활용이 강점이다. 향후 Control API 연동 시 제안된 분위기를 자동 적용할 수 있고, 사용자 패턴 학습과 가족 케어로 확장 가능하다.

## 7. 개발 계획
4주 일정으로 프로토타입 구현 가능

- 1주: SDK 연동 및 데이터 수집 (조향각 버퍼, 운전 시간, 경로)
- 2주: 리듬 점수 계산 + 마이크로 스토리 생성 로직
- 3주: UI (파동 시각화, 호흡 가이드, 현재 vs 제안 대비)
- 4주: 테스트 및 데모 영상

향후 TTS·Vehicle Control API가 열리면 음성 안내와 공조·라이트 자동 적용으로 확장한다.


## 8. 프로토타입 구현 기준 (2026-10-28)

- 1초 간격으로 관찰하고 최근 30초 창에서 평균 조향 변화량·방향 반전·브레이크 밟음 전이를 계산한다. 실제 차량은 최소 12개 표본, 명시적 시연은 5개 표본을 기다린다.
- 프로토타입 지표는 `100 − 평균 조향 변화량×6 − 유의한 방향 반전×2.5 − 브레이크 전이×2`를 0~100으로 제한한다. 1.2° 미만의 변화는 방향 반전 집계에서 제외한다. 이 상수는 실차 검증 전 가설이며 운전자 건강·안전 점수가 아니다.
- 점수가 55 미만인 관찰이 3회 이어지면 큰 변화로 표시하고, 72 이상이 6회 이어져야 회복 상태로 전환한다. 시간 창의 이전 관찰도 유지해 순간 변화에 반응하지 않는다.
- 방향지시등·200m 이내 TBT 회전·18° 초과 조향·10km/h 미만 구간은 분석에서 제외한다. 신호와 기어는 5초 안에 재확인되어야 하며, 연결 누락과 긴 수집 공백은 창을 초기화한다. 속도 미제공 시 속도 기반 제외 조건은 적용할 수 없어 연결 화면에 표시한다.
- 차량 운전 시간 API가 미지원이면 앱에서 측정한 기록 시간과 주행 관찰 시간을 별도 표시한다. 실제 차량 값과 시연 값을 혼합해 리포트를 만들지 않는다.
- 기록은 사용자가 주차 상태에서 시작하며, 포그라운드 서비스로 수집한다. 15초마다 중간 상태를 저장한다. 프로세스가 종료되면 마지막 중간 저장 시점까지를 중단 기록으로 복구하며 미관찰 시간을 채우지 않는다.
- 리포트는 분석 가능한 구간의 비율을 함께 표시한다. 자료가 부족하면 점수·일정한 리듬 비율은 비워둔다. 시연 기록은 표시하고 주간 합계에서 제외한다.
- 최근 60개 기록을 기기에 보관한다. 서버 전송과 자동 공조·라이트 쓰기는 구현 범위에 포함하지 않는다. 음성 안내는 사용 가능한 기기 한국어 TTS를 이용한다.
- AAOS 제한에 맞춰 주행 중 조작을 줄인다. 진입 Activity가 DO를 선언하며, 이 구현만으로 OEM의 승인이나 실차 검증 완료를 의미하지 않는다. 상세 UI 구조와 조사 근거는 9절에 따른다.

### 화면과 흐름

- 주차 홈: 왼쪽의 고정 탐색(지금·기록·쉼·연결), 큰 현재 상태와 주행 기록·30초 숨 고르기 버튼, 오른쪽의 정적인 길 일러스트. 미리보기는 상단의 주행 화면 버튼, 시연은 별도 선택 창에서 시작한다.
- 주행: 큰 상태·리듬 일러스트와 한두 줄 문장, 경로 요약, 기록 여부와 음성 안내 제어만 표시한다. 시연에서도 가상 D/P 상태에 따라 주행·주차 화면이 바뀐다.
- 쉼: 주차 중 호흡 시작, 현재 실내 상태와 제안 비교. 호흡은 계속 주차·앱 활성 상태를 요구한다.
- 기록·연결: 자세한 리포트, 데이터 출처, 미지원 값, 음성 설정을 주차 상태에서 확인한다.
- 앱 진입 화면도 주차 여부가 불명확하면 제한된 요약만 표시한다. 같은 Activity 안에서 주행 상태에 따라 레이아웃을 전환하며, P가 확인되면 주차 화면으로 돌아온다. 앱 아이콘과 기록 알림의 진입점도 동일하다. 화면 전환 때 새로운 앱 작업을 만들지 않아 GNB에 중복 앱 항목을 추가하지 않는다.

### 시각 방향 (0.4.0)

기획의 ‘인카 동반자’에 맞춰 따뜻하고 산뜻한 색을 사용한다. 주간 바탕은 크림색 `#F6F3EB`, 기본 글자는 짙은 녹회색 `#2E3F3C`, 주요 버튼은 짙은 녹청색 `#32645E`다. 정적인 길 일러스트에 하늘색·세이지색·살구색을 사용하고, 쉬어갈 때의 제안은 살구색 `#F6E5D9`로 구분한다. 리듬 표시는 파랑 `#315F83`, 변화·쉼 제안은 주황 `#98502F`를 사용한다. 밝은 배경에서도 정보는 진한 글자로 표시한다.

시스템 야간 설정에 따라 짙은 녹색 `#25322D` 바탕과 밝은 녹청색 버튼, 달이 있는 장면으로 전환한다. 큰 터치 영역과 주행 중 정적 요약을 유지한다. 대비 계산은 주요 글자·버튼·상태 배지 조합을 대상으로 하며 실제 차량의 반사·주야간 시인성 검증을 대신하지 않는다.

DO 선언은 개발자가 특정 Activity의 제한된 동작을 선언하는 방식이다. 이를 OEM의 심사·배포 승인으로 해석하지 않는다. 앱 카테고리와 지역별 허용 범위, 실차의 물리 글자 크기·시인성·주간 반사·시선 이탈 시간은 제출 전 검증한다. 제한을 해제하는 ADB 명령이나 시스템 허용 목록 수정은 사용하지 않는다.

### 구현 방향: 산뜻한 여행 동반자

- **주차 홈:** 큰 빈 색상 카드 대신 하나의 연속된 화면을 사용한다. 왼쪽에는 현재 상태·짧은 문장·주행 기록 시작, 오른쪽에는 정적인 ‘길과 리듬’ 대표 그래픽을 배치한다. 경로가 설정된 경우에만 목적지·남은 시간을 보조 정보로 확장한다. 경로 미설정 안내는 짧은 한 줄과 큰 내비 조작 영역으로 축소한다.
- **조작 위계:** 채워진 녹청색 ‘주행 기록 시작’을 주 행동, 테두리형 ‘30초 숨 고르기’를 보조 행동으로 구분한다. 미리보기는 상단, 시연은 왼쪽 아래에 배치한다. 일반 버튼 112dp·주 행동 128dp의 터치 영역을 유지한다.
- **대표 그래픽:** 큰 빛 번짐·장식용 작은 파형 대신 2~3개의 면과 곡선으로 길·바람·짧은 쉼을 표현한다. 이는 브랜드 일러스트이며 실제 관찰 파형처럼 표시하지 않는다. 실제 조향 파형은 관찰 데이터와 범례가 있는 주차 상세 화면에서 제공한다.
- **색과 글자:** 밝은 중립색을 기본 바탕으로 삼고, 데이터의 파랑·주황 의미를 유지한다. 버튼·선택 상태·그래픽에서 주조색을 반복해 통일감을 만든다. 넓은 주차 홈 제목은 72sp, 주행 핵심 상태는 최대 64sp다. 주요 활성 글자·버튼·배지의 새 조합은 주간 4.69:1 이상, 야간 4.50:1 이상이며 주 버튼 자체는 각각 6.73:1·7.87:1이다.
- **주행 화면:** 큰 상태·짧은 문장과 활성 경로의 요약을 표시한다. 신호 대기 상태는 대기 이유를 명시한다. 0.4.2에서 정적인 상태 일러스트를 추가하고 0.4.3에서 작은 반복 움직임을 시범 적용했다. 파랑·하늘색은 일정·변화 관찰 상태, 살구색·주황은 큰 리듬 변화를 나타내며 문장으로도 상태를 구분한다.
- **쉼과 작은 창:** 넓은 쉼 화면은 안내·풍경과 실내 비교·시작 버튼을 나란히 둔다. 좁은 창에서는 일러스트와 보조 정보를 줄여 큰 행동 버튼을 우선한다. 실내 비교는 공간이 좁으면 세로로 배치한다.

이 방향은 [Pleos 기본 디자인 원칙](https://document.pleos.ai/docs/connect/guide/docs-design/Introduction/intro)의 간결한 전달·일관성·주행 중 애니메이션 제한과 [Google 차량용 시각 원칙](https://developers.google.com/cars/design/design-foundations/visual-principles)의 큰 터치 영역·대비·야간 시인성을 제약 조건으로 삼는다. ‘예쁘게 보이는가’는 비교 시안과 실제 표시 크기로 평가하고, 운전 중 인지 성능은 별도로 검증한다.

이번 조사 이미지·원본 링크와 비교 보드는 로컬 `.tools/research/ui-2026-10-28/`에 보관한다. 참고 이미지의 저작권은 각 제작사에 있으며 앱 배포 자산으로 포함하지 않는다.

### 주행 화면 시각 보강 (0.4.2 · 2026-10-29)

‘리듬 기록 중’ 화면의 빈 공간을 줄이고 큰 상태·짧은 문장과 정적인 리듬 풍경을 함께 배치했다. 넓은 화면에서는 글과 그림을 나란히 두며 경로 요약이 있으면 그림을 아래로 배치한다. 작은 창에서는 그림을 짧은 리듬 심볼로 줄여 글자 크기를 유지한다. 기록 중 표시에는 점을 더하되 깜빡임이나 맥동을 사용하지 않는다.

`ui/RhythmIllustration.kt`는 분류 상태별 고정 곡선과 색면으로 구성한 원본 벡터 일러스트다. 실제 신호의 추이·경로·진행률을 표현하지 않는다. 일정·중간 변화·큰 변화의 고정 형태를 구분하고, 학습·신호 없음·회전 등 분석 제외 상태에서는 곡선 대신 정적인 세 개의 짧은 선을 표시한다. 데이터가 없는데 일정한 리듬으로 보이게 하지 않으며, 실시간 파형·반복 애니메이션·새로운 주행 중 조작은 추가하지 않는다. 주야간 색상은 기존 팔레트를 사용하고 수집·분류·저장 규칙은 유지한다.

두 변형의 빌드·단위 테스트(각 22개)·lint 오류 0개를 확인했다. 기존 UI 검사 48개와 별도 상태·주야간·크기별 UI 검사 34개를 통과했다. 새 배경의 주요 글자 대비는 최소 4.86:1이며 실제 운전자의 시선 이탈은 측정하지 않았다. 상태별 화면 검사는 저장소에 기록하지 않는 합성 UI 상태로 수행했고, 영상은 실제 앱의 ‘여정 시연’을 다시 녹화했다. 검사 로그는 로컬 `.tools/logs/rhythm-visual-*`, 캡처는 `.tools/screenshots/rhythm-ui-*.png`에 보관한다.

### 주행 파동의 잔잔한 움직임 (0.4.3 · 2026-10-29)

사용자 요청에 따라 일정·중간 변화·큰 변화 상태에서 일러스트의 곡선이 12초 주기로 작게 움직이도록 시범 구현했다. 큰 파동 제어점의 이동 범위는 각 방향 최대 4dp, 작은 심볼은 최대 1.5dp이며 높이의 2.5% 이내로 추가 제한한다. 양 끝점·글자·배경·풍경은 고정한다. 큰 그림이 있으면 작은 심볼을 고정해 한 곳만 움직인다. 상태가 같아도 움직임을 이어가며, 학습·연결 대기·회전 등 분석 제외 상태와 화면 이탈·앱 비활성 상태에서는 반복 애니메이션을 실행하지 않는다. 움직임은 센서 수치·호흡 안내·안정도 개선을 표현하지 않으며 차량 데이터 수집·분류·저장 규칙은 유지한다.

이는 [Pleos 주행 안전 설계](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline)의 장식적·반복적 움직임 지양 원칙에 대해 별도 검토가 필요한 시범 디자인이다. 느린 속도나 작은 이동 범위만으로 공식 가이드 충족·심사 승인·시선 분산 감소를 입증하지 않는다. 현재 검증은 에뮬레이터의 표시 동작 범위다.

두 앱 변형의 빌드·단위 테스트(각 22개)·lint 오류 0개, 기존 UI 48개와 리듬 UI 45개 검사를 통과했다. 리듬 UI는 같은 분류를 유지한 화면을 3초 간격으로 캡처해 주간·야간·작은 창에서 실제 픽셀 변화가 있는지, 제목 글자는 고정되는지, 신호 대기 상태에서는 움직임이 없는지 검사한다. 결과는 `.tools/logs/rhythm-motion-*`, 비교 프레임은 `.tools/screenshots/rhythm-motion/`에 보관한다. 이는 시선 영향 측정이 아니다.

### 목적지·도착 정보 카드 개편 (0.4.4 · 2026-10-29)

`ui/RouteSummary.kt`는 넓은 주행 화면 오른쪽의 경로 요약을 세이지색 카드로 구성한다. 위쪽에는 목적지와 정적인 핀 일러스트, 가운데에는 최대 96sp의 남은 시간과 거리·도착 예상 시각, 아래에는 다음 안내를 배치한다. 목적지는 최대 3줄, 다음 안내는 최대 3줄까지 표시한다. 보조 글자는 24sp 이상이다. 작은 세로 창에서는 목적지·남은 시간·거리를 먼저 표시하고 도착 예상 시각과 장식 핀은 생략한다. 새 조작이나 추가 애니메이션은 없다.

남은 시간은 분 단위 올림, 1km 미만은 m로 표시한다. 도착 예상 시각은 내비의 남은 초를 기기 시계에 더한 추정값이며 약 15초 간격으로 시계를 갱신한다. 누락·음수 값은 ‘확인 중’, 목적지·TBT 누락은 대기 문구로 표시한다. 핀은 목적지를 나타내는 장식으로 실제 경로 형상이나 이동 진행률을 표현하지 않는다. NaviHelper의 수신·저장·도착 판정은 유지한다. 주요 글자 대비는 주간 최소 5.19:1, 야간 최소 5.60:1이다.

## 11. 상황별 주차 홈과 여정 요약 (0.4.1 · 2026-10-29)

큰 제목은 시간대별 출발 인사, 기록 시작, 주행 후 잠깐 주차, 한 시간 이상 주행 후 주차, 최근 여정 종료로 구분한다. 한 시간은 앱이 기록한 실제 주행 시간으로 판단하고 주차 대기 시간은 포함하지 않는다. 기록을 마친 뒤 30분 동안은 ‘이번 여정도, 수고했어요’로 인사한다. 이는 화면 문구의 유지 시간이며 운전자의 피로나 안전을 판단하는 기준이 아니다. 중단 기록이나 미래 시각의 기록에는 종료 인사를 사용하지 않는다. 주차 문구는 출발·주차 상황을 우선해 동승자 안내가 반복되는 현상을 줄인다.

넓은 홈은 일러스트 아래에 여정 요약을 배치하고, 좁은 홈은 제목 아래의 짧은 요약으로 표시한다. 기록 중이면 현재 여정, 그 외에는 종료 시각이 가장 최근인 실제 기록을 선택한다. 현재 시연은 ‘이번 시연 여정’으로 구분하며 저장된 시연 이력은 실제 직전 여정에서 제외한다. 중단 기록은 중단 표시와 함께 관찰된 부분만 설명한다.

리듬 요약은 저장된 일정 구간 시간 / 분석 구간 시간의 비율이다. 예를 들어 주행 20분 중 10분을 분석하고 그중 8분이 일정했다면 ‘분석 구간의 80%가 일정한 리듬이었어요’와 ‘분석 10분 / 주행 20분’을 표시한다. 미관찰 구간을 일정한 리듬으로 간주하지 않는다. 분석 가능한 구간이 없거나 수치가 맞지 않으면 비율 대신 분석 부족을 표시한다. 실제 기록이 없으면 첫 주행의 리듬을 기다리는 상태를 표시한다. 호흡 횟수는 이 비율과 제목의 주행 판단에 영향을 주지 않는다.

인사와 요약은 주차 홈의 표현만 바꾼다. 주행 중 요약, 주차 판정, 수집·저장·리듬 분류 규칙은 8~10절을 따른다. 시간대와 종료 인사는 주차 홈에서 약 1분 간격으로 갱신한다.
