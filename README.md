## 한 줄 소개
조향각·브레이크 패턴의 변화를 읽고, 주차 후 30초 숨 고르기와 도착 리포트로 이어지는 인카 동반자

## 핵심 기능
- **운전 리듬 시각화**: 조향각·브레이크 패턴을 파동으로 표현
- **마이크로 스토리**: 데이터 조건 조합으로 생성되는 짧은 공감 문장
- **숨 고르기 가이드**: 주차 상태에서 30초 호흡 가이드 + 차량 파형·호흡 파형 비교
- **경로 연동**: NaviHelper를 활용한 분위기 제안
- **도착 리포트**: 오늘의 운전 리듬 요약

## 기획에서 활용할 API
- Vehicle State: `CAR_DRIVE`, `CAR_CLIMATE`, `CAR_LIGHTS`, `CAR_SEATS` 등
- NaviHelper: 경로, 목적지, TBT
- TextToSpeech: 리듬 변화 제안과 주차 중 호흡 안내 음성 (온디바이스 모드)

## 구현 현황 (0.4.6 · Pleos 음성 안내)

| 기능 | 구현 |
| --- | --- |
| 차량 리듬 | 조향·브레이크 실시간 구독 및 조회, 최근 30초 분석, 최근 90초 파형 |
| 마이크로 스토리 | 리듬·운전 시간·시간대·경로·좌석 정보를 조합한 결정형 문장 |
| 숨 고르기 | 주차 확인, 3초 들숨·3초 날숨 5회, 원형 안내, 차량·호흡 파형 비교 |
| 실내 분위기 | 현재 실내 온도·설정 온도·조명 조회와 제안 상태 비교 |
| 경로 | NaviHelper 연결, 목적지·남은 시간·거리·TBT, 기본 내비 열기, 도착 이벤트 |
| 리포트 | 기록 시간·분석 범위·리듬 변화·브레이크·호흡 기록, 도착·수동 종료 저장 |
| 기록 보관 | 기기 내부 최근 60회, 최근 7일 합계, 상세 조회·개별 삭제, 중단 기록 복구 |
| 음성 | Pleos TextToSpeech SDK(온디바이스)로 짧은 제안 및 주차 중 호흡 안내. Pleos 음성이 없으면 기기 한국어 TTS, 그것도 없으면 화면 안내 |
| 시연 | 일정·변화·회전·연결 끊김·주차 장면, 시연 표시, 주간 실주행 합계 제외 |
| 주행 중 제한 | 주행·주차 화면 분리, AAOS 제한·실제 기어 확인, 주차 후 기능 복귀 |

`demoDebug`는 일반 Android용이며 가상 주차 차량을 제공한다. `pleosDebug`는 실제 Pleos Vehicle·NaviHelper SDK를 사용하며, 주차 상태에서 가상 여정 시연도 실행할 수 있다. 사용자가 시작한 기록은 포그라운드 서비스로 앱을 나가도 계속된다.

리듬 점수는 신호 변화의 프로토타입 규칙이다. 회전·저속·신호 누락은 분석에서 제외하며, 호흡 완료 자체로 주행 점수를 올리지 않는다. 실제 차량 보정과 실주행 평가는 별도 단계다.

현재 에뮬레이터의 차량 운전 시간 API는 미지원이므로 **앱 기록 시간**으로 출처를 구분한다. 내비 정보는 설치된 내비 제공자가 반환하는 범위에서 표시한다. 공조·라이트 자동 제어는 기준 기획서의 향후 확장 기능이며 현재는 제안만 제공한다.

## 차량용 UI/UX 적용

[기준 문서의 리서치·적용 내역](docs/drive-mood-planning-full.md#9-차량용-uiux-리서치와-적용-2026-10-28)에 공식 출처와 선택 이유를 정리했다. 큰 상태와 짧은 문장, 일반 버튼 112dp·주요 버튼 128dp와 32sp 글자, 고정 탐색, 스크롤 없는 주행 요약을 적용했다. `MainActivity` 하나를 DO 진입점으로 사용하고 주행·주차 레이아웃을 분리했다. 주차 상태가 확인되기 전에는 요약만 표시하고 상세 기능은 차단한다.

주차 홈은 왼쪽의 큰 상태·기록 시작·숨 고르기와 오른쪽의 정적인 길 일러스트로 구성한다. 경로 미설정 안내는 아래 한 줄로, 미리보기는 상단으로 정리했다. 크림색 바탕과 녹청색 주 버튼, 테두리형 보조 버튼을 사용하고 시스템 야간 모드에서는 짙은 녹색·달이 있는 장면으로 전환한다. 파랑 리듬·주황 변화의 의미는 유지한다. 실제 사례 비교와 선택 이유는 기준 문서 10절에 기록했다.

0.4.1 주차 홈은 시간대·기록 시작·주행 후 주차·장거리 주행 후 주차·최근 기록 종료에 맞춰 인사한다. 기록 중에는 이번 여정, 그 외에는 가장 최근의 실제 여정을 요약한다. 일정한 리듬의 비율은 **분석된 구간 기준**으로 표시하며 분석 시간과 주행 시간을 함께 제공한다. 시연 이력은 실제 직전 여정에서 제외하고, 분석 부족·중단 기록은 명시한다.

실제 앱 화면으로 제작한 [한글 자막 시연 영상](artifacts/video/DriveMood_demo_ko_1080p.mp4)이 있다. 1분 40초·1080p·정상 속도의 30초 호흡을 포함한다. [14초 파동 움직임 미리보기](artifacts/video/DriveMood_rhythm_motion_14s.mp4)는 일정한 상태가 유지되는 시연 구간을 정상 속도로 담았다. 녹화 범위와 재제작 방법은 [시연 대본](docs/drive-mood-demo-script.md)에 정리했다.

주행 화면에는 큰 리듬 상태·짧은 문장과 리듬 풍경을 함께 표시한다. 상태별 파랑·살구 배경과 곡선으로 흐름을 구분한다. 0.4.3은 사용자 요청에 따라 상태가 일정해도 파동이 12초 주기로 최대 4dp만 움직이는 시범 구현이다. 글자·배경·파동 양 끝은 고정하고, 학습·신호 대기·분석 제외 상태는 움직이지 않는다. 작은 창에서는 작은 심볼 하나만 움직인다. 그림의 움직임은 센서 측정값·경로·호흡 안내를 표현하지 않는다. 주행 중 반복 장식의 제출 적합성과 실제 시선 영향은 검증하지 않았으며, [기준 문서의 시범 적용 범위](docs/drive-mood-planning-full.md#주행-파동의-잔잔한-움직임-043--2026-10-29)에 기록했다.

0.4.4의 [경로 카드 미리보기](artifacts/video/DriveMood_route_card.png)는 세이지색 바탕과 목적지 핀, 큰 남은 시간, 거리·도착 예상 시각, 다음 안내로 구성한다. 도착 예상 시각은 기기 현재 시각에 내비의 남은 시간을 더한 추정값이다. 정보가 누락되거나 음수이면 확인 중으로 표시하며, 가까운 거리는 m 단위로 표시한다. 세로 공간이 짧으면 목적지·시간·거리·다음 안내를 우선한다.

0.4.5는 실차 대비 보강이다. 기어는 바뀔 때만 알려주는 차량 속성이라, 5초 재확인을 지원 종료 예정인 SDK 조회에만 맡기지 않고 Android 차량 속성도 1초마다 직접 읽는다. 시연 기록 중에는 '다시 연결'로 실제 차량 상태가 초기화되어 시연이 중단되는 일을 막고, 주차 확인 불가와 실제 주차 해제를 구분해 안내한다. 주차 홈의 경로 줄도 경로 카드와 같은 규칙(1km 미만 m, 음수·누락 미표시)을 쓴다.

0.4.6은 음성 안내를 Pleos TextToSpeech SDK로 옮겼다. 온디바이스(`ON_DEVICE`) 모드라 네트워크와 Pleos Playground 앱 인증 정보(Client ID·Secret)가 필요 없고, `pleos.car.permission.TTS_SERVICE` 권한 선언만 사용한다. 음성은 차량 음성 서비스가 재생한다. Pleos 음성을 쓸 수 없는 환경에서는 기기 한국어 TTS로, 그것도 없으면 화면 안내로 대체한다. `demoDebug`는 일반 Android용이라 기기 TTS를 그대로 쓴다.

앱의 **주행 화면** 버튼으로 주차 상태에서 미리 보거나, 왼쪽 **시연 → 여정 시연**에서 D/P 전환을 확인할 수 있다. 기록을 시작한 뒤 D로 전환하면 주행 요약을 표시하고, P가 확인되면 주차 홈으로 돌아온다.

## 실행 방법

설치된 개발 도구로 데모 APK를 빌드한다.

```bash
./scripts/gradle.sh :app:assembleDemoDebug
```

APK 위치: `app/build/outputs/apk/demo/debug/app-demo-debug.apk`

Pleos SDK를 포함한 APK를 빌드한다.

```bash
./scripts/gradle.sh :app:assemblePleosDebug
```

APK 위치: `app/build/outputs/apk/pleos/debug/app-pleos-debug.apk`

Android Studio는 `./scripts/studio.sh`로 연다. 최초 설치 및 에뮬레이터 설정은 [개발 환경 안내](docs/development-setup.md)를 따른다.

## 테스트 환경

- 최소 Android API 28, 컴파일 API 36, 타깃 API 34 (Pleos Connect 2.1.0 실행 환경)
- Java 21 실행 환경, Java/Kotlin 바이트코드 타깃 17
- Gradle 8.13 / Android Gradle Plugin 8.11.1 / Kotlin 2.2.21
- Vehicle SDK 2.3.2 / NaviHelper SDK 3.0.5 / TextToSpeech SDK 3.3.1
- Pleos Connect Emulator 2.1.0 (Android API 34), 전용 기기 프로필 2560×1440 / 160dpi

## 검증

```bash
./scripts/gradle.sh :app:testDemoDebugUnitTest :app:testPleosDebugUnitTest \
  :app:lintDemoDebug :app:lintPleosDebug
```

에뮬레이터 전체 흐름 검증은 [개발 환경 안내](docs/development-setup.md#7-검증-명령)를 참고한다. 두 APK는 개발용 debug 서명이다. 제출용 서명과 실차·제공자별 검증은 별도로 진행한다.
